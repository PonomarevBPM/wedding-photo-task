# Любовь в кадре

Мобильное приложение для свадебных фотозаданий: обязательное имя гостя, четыре случайных задания, камера или галерея, превью сжатого JPEG и отправка в приватный архив организатора на Яндекс Диске.

## Локальный запуск

Используйте Node.js 22 LTS или новее.

```sh
npm install
npm run dev
```

Откройте http://localhost:3000. Интерфейс и подготовка фотографий работают без токена; отправка покажет, что архив ещё не подключён. Успех не имитируется.

Для подключения архива создайте `.env.local` по образцу `.env.example` и укажите серверный `YANDEX_DISK_TOKEN`. Получите OAuth-токен через собственное приложение Яндекса с правами чтения метаданных, создания папок и загрузки файлов. Документация: [API Яндекс Диска](https://yandex.ru/dev/disk/rest/) и [Яндекс OAuth](https://yandex.ru/dev/id/doc/ru/).

`YANDEX_DISK_ROOT` задаёт корневую папку (`disk:/wedding` по умолчанию). Для токена, ограниченного папкой приложения, используйте `app:/wedding`. Перезапустите dev-сервер после изменения окружения. Не добавляйте токен в Git, клиентские переменные `NEXT_PUBLIC_*` или переписку.

Для просмотра с телефона в одной Wi-Fi-сети используйте `http://<локальный-IP-компьютера>:3000`. Нативная съёмка через файловое поле зависит от браузера; для финальной проверки используйте HTTPS-развёртывание и реальные Safari/Chrome. HEIC поддерживается, если браузер умеет декодировать файл; иначе приложение предлагает новый снимок или JPEG из галереи.

## Проверки

```sh
npm run typecheck
npm run build
```

Автотесты не добавлены по договорённости. Сборка и проверка типов не подтверждают реальную загрузку на Диск и работу камеры: это нужно проверить вручную после настройки токена и на реальных телефонах.

## Размещение на VPS

По SSH-проверке 15 октября 2026 года на VPS с Ubuntu 22.04 x86_64 уже настроены Nginx, HTTPS и автопродление через Snap. Отсутствуют Docker, Compose, `rsync`, пользователь `deploy` и каталог приложения. Установка недостающего и настройка SSH описаны по порядку в [инструкции деплоя](deploy/GITHUB_ACTIONS.md). Nginx проксирует домен `https://wedding-dinner.ru` на `127.0.0.1:3100`; рабочая конфигурация — `/etc/nginx/sites-available/default`. Старые сайты удалены пользователем. Результаты проверки и команды управления: [deploy/README.md](deploy/README.md).

Автоматический деплой после push в `main`: [настройка GitHub Actions](deploy/GITHUB_ACTIONS.md). Образ собирается на GitHub и передаётся по SSH; токен Диска хранится только на VPS. При этом способе используйте команды управления из инструкции GitHub Actions.

Production-приложение собирается в standalone-режиме и получает секреты из серверного `.env.local` при запуске. Nginx принимает запросы до 4 МБ и ждёт ответ приложения до 90 секунд. Ограничение частоты отправок в текущем конфиге не настроено. Доступ гостей — по ссылке, без пароля. Папка Диска не публикуется. До первого запуска контейнера сайт может отвечать 502.

Чтобы закрыть приём, установите `PHOTO_UPLOADS_ENABLED=false` в серверном `.env.local` и пересоздайте контейнер. При ручной установке: `sudo docker compose up -d --force-recreate app`; при деплое через Actions используйте команду с двумя Compose-файлами из [инструкции](deploy/GITHUB_ACTIONS.md).

## Архив и настройки

Фото: `<корень>/wedding/<task-id>/<имя-гостя>__<upload-id>.jpg`. Идентификатор отправки сохраняется при повторе сетевого запроса, существующее фото не перезаписывается. На Диск загружаются только фотографии. Метаданные и размер сохранённого файла проверяются перед подтверждением успеха.

Название мероприятия и задания меняются в `src/lib/event.ts`. Стабильные идентификаторы заданий нужны для организации папок. Имена молодожёнов пока не заданы, поэтому используется нейтральное название.

Фото уменьшается до 2560 пикселей по длинной стороне и сжимается до 3 МБ; превью показывает именно отправляемый файл. Фото сохраняется в открытой странице при ошибке, но не переживает её перезагрузку или закрытие.
