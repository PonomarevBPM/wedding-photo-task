# План: свадебные фотозадания

## Идея

Мобильное веб-приложение, в котором гости свадьбы получают задания о молодожёнах, делают фотографии и отправляют их в общий архив. Приложение открывается по ссылке или QR-коду в браузере смартфона, без установки.

Согласованный стартовый набор из четырёх заданий:

- Сфотографируй, как жених улыбается.
- Поймай момент, когда жених обнимается с друзьями.
- Сфотографируй невесту с подругами.
- Сделай совместное фото с молодожёнами.

## Сценарий гостя

1. Гость открывает приложение, видит короткое приветствие и вводит обязательное имя. На этом устройстве имя запоминается; его можно изменить.
2. Получает случайное фотозадание. Кнопка «Другое задание» предлагает другое из набора.
3. Нажимает «Сделать фото» — открывается камера смартфона.
4. После съёмки видит превью фотографии и текст задания.
5. Может переснять фотографию или нажать «Отправить».
6. Во время отправки видит состояние загрузки; повторное нажатие блокируется.
7. После подтверждённого сохранения видит «Фото отправлено» и может сделать ещё фото по этому заданию или получить другое.
8. При ошибке видит понятное сообщение и может повторить отправку без повторной съёмки, пока страница открыта.

## Первая версия (MVP)

- Интерфейс на русском языке, рассчитанный прежде всего на смартфоны: крупные кнопки, короткие тексты, минимум действий.
- Заранее подготовленный набор заданий, случайная выдача и кнопка «Другое задание».
- Одинаковые задания могут получать разные гости; несколько фотографий по одному заданию разрешены.
- Обязательное имя гостя без регистрации и проверки личности. Имя передаётся вместе с каждой фотографией.
- Съёмка через штатную камеру телефона и возможность выбрать готовое фото из галереи.
- Превью с кнопками «Переснять» и «Отправить».
- Загрузка в выделенную папку на Яндекс Диске организатора.
- Состояния отправки, успеха и ошибки.
- Вход по общей ссылке или QR-коду мероприятия без пароля и регистрации гостей.

Админку, публичную фотогалерею, рейтинг гостей и проверку соответствия фотографии заданию можно добавить позже. Для первой версии задания хранятся в конфигурации проекта, а организатор просматривает фотографии на Диске.

## Камера и фотографии

Для первой версии использовать файловое поле с `accept="image/*"` и `capture="environment"`: оно предлагает съёмку основной камерой на поддерживающих это смартфонах. Поведение зависит от браузера, поэтому доступ к галерее нужен как запасной сценарий. Источник: [MDN — capture](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture).

Отдельный экран с живым изображением камеры внутри сайта можно сделать позже, если штатного интерфейса окажется недостаточно.

Перед отправкой проверять формат и размер фотографии, корректно показывать её ориентацию, уменьшать разрешение при необходимости и сжимать в JPEG. Сжатие согласовано; сохранять оригиналы в первой версии не требуется. Рабочий предел готового файла — 3 МБ; точные настройки качества подобрать на реальных фотографиях. Превью должно показывать подготовленную к отправке фотографию. Отдельно проверить фотографии с iPhone, включая HEIC.

## Хранение и загрузка

Предпочтительное хранилище — Яндекс Диск; окончательный выбор подтвердить при проверке интеграции. Все фотографии поступают в аккаунт организатора, гостям не нужен аккаунт Яндекса. Для интеграции использовать [REST API Яндекс Диска](https://yandex.ru/dev/disk/rest/).

Предлагаемая схема MVP:

1. Браузер подготавливает фото и отправляет его вместе с именем гостя, идентификатором задания и отправки в серверный API приложения.
2. Сервер проверяет файл, задание и то, что приём фотографий открыт, сам формирует путь сохранения.
3. Сервер с OAuth-токеном организатора получает ссылку загрузки у Яндекс Диска и передаёт туда файл.
4. Приложение показывает успех только после подтверждения сохранения.

OAuth-токен хранится в серверном `.env.local` на VPS, передаётся контейнеру при запуске и не передаётся в браузер. Папки организуются по мероприятию и заданию. Путь: `wedding/<event-id>/<task-id>/<safe-guest-name>__<upload-id>.jpg`; имя очищается сервером и не используется как идентификатор гостя. Уникальный идентификатор отправки используется повторно при сетевом сбое, чтобы повтор запроса не создавал лишнюю фотографию. На Диск загружаются только фотографии, без JSON со списком заданий.

Согласованный предел фотографии — 3 МБ. Сервер ограничивает размер файла и тела запроса; в Nginx задаётся `client_max_body_size 4m`, чтобы фотография с полями формы проходила к приложению.

Если потребуется сохранять большие оригиналы, отдельно проверить прямую загрузку из браузера по выданной сервером ссылке Яндекс Диска, включая CORS. До этой проверки не считать такой вариант гарантированно рабочим; при необходимости выбрать промежуточное хранилище с поддержкой прямых загрузок.

## Технологии и размещение

Предлагаемый стек — Next.js и TypeScript: мобильный интерфейс и серверный API в одном проекте. Отдельная база данных для MVP не требуется, если задания фиксированы, а фотографии и их привязка к заданиям хранятся на Диске.

Приложение размещается на VPS с Ubuntu через Docker Compose и обновляется GitHub Actions после push в `main`. Nginx уже настроен на Ubuntu и проксирует запросы в контейнер на `127.0.0.1:3100`; рабочий сайт — `/etc/nginx/sites-available/default`. Постоянный адрес — `https://wedding-dinner.ru`, сертификат Let’s Encrypt установлен, автопродление включено через `snap.certbot.renew.timer`. Деплой обновляет только приложение, существующие Nginx и сертификаты сохраняются. Инструкция: [deploy/README.md](deploy/README.md).

Перед свадьбой проверить HTTPS, доступность сайта из России и отправку фото через мобильный интернет и Wi-Fi площадки. Фотографии сохраняются на Диске и не зависят от локальной файловой системы контейнера.

## Доступ и устойчивость

- Доступ по ссылке или QR-коду без пароля. Любой человек с этой ссылкой может отправить фото, пока приём открыт.
- Проверка типа и размера файла на сервере, ограничение частоты отправок и закрытие приёма после мероприятия.
- Фотографии по умолчанию доступны организатору; публичный доступ включается отдельным решением.
- При сетевой ошибке сохранять выбранное фото в текущей странице и предлагать повторить отправку. Сохранение после закрытия или перезагрузки страницы в MVP не гарантируется.
- Перед запуском проверить свободное место на Диске и работу токена.

## Порядок реализации

1. Использовать четыре согласованных задания, случайную выдачу и сжатие фотографий.
2. Проверить интеграцию: фотография через серверный API попадает в нужную папку Яндекс Диска из приложения на VPS.
3. Сделать мобильный сценарий: задание → камера → превью → отправка → результат.
4. Добавить проверки файлов, защиту загрузки и повтор отправки при ошибках.
5. Проверить на реальных iPhone/Safari и Android/Chrome: камера, галерея, ориентация, большие фото и плохая сеть.
6. Подготовить финальные тексты и оформление, разместить приложение и сделать QR-код постоянной ссылки.

Готовность первой версии: гость открывает приложение на смартфоне, указывает имя, получает случайное задание, делает фото и подтверждает его в превью. Организатор получает сжатую фотографию с именем автора в папке соответствующего задания на Диске. Подробный план работ: [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md).
